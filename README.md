# HSEduTrack

เว็บตรวจสอบคะแนนนักเรียน โดยใช้ Google Sheet เก็บข้อมูล และ Google Apps Script เป็นตัวกลางรับส่งข้อมูล

## ไฟล์หลัก

- `index.html` — หน้าเว็บและโค้ดการทำงาน
- `sprites/` — ภาพตัวละคร
- `sprites_db.js` และ `sprites_db.json` — ข้อมูลตัวละคร

เว็บรุ่นนี้ใช้ Google Sheet เป็นแหล่งข้อมูลคะแนนเพียงแห่งเดียว โค้ด Supabase เดิมถูกปิดการซิงค์เพื่อไม่ให้ข้อมูลจากอีกฐานกลับมาทับคะแนน แม้เครื่องเคยเก็บการตั้งค่า Supabase ไว้

## ประวัติการแก้ไขด้วย Git

Git เก็บประวัติโค้ดไว้ในเครื่อง สามารถตรวจสอบการเปลี่ยนแปลงได้ด้วย:

```powershell
git status
git diff
git log --oneline
```

เมื่อแก้เว็บและตรวจสอบเรียบร้อยแล้ว ให้เลือกไฟล์ที่ต้องการบันทึก เช่น:

```powershell
git add index.html
git commit -m "Describe the change"
```

ไฟล์สำรอง ข้อมูลนักเรียนที่ส่งออก และไฟล์ความลับต้องไม่ถูกเพิ่มเข้า Git โฟลเดอร์ `backups/` และ `exports/` ถูกยกเว้นไว้ใน `.gitignore`

## การสำรองข้อมูล

ไฟล์เว็บต้นฉบับก่อนเริ่มใช้ Git อยู่ใน `backups/` แยกโฟลเดอร์ตามวันเวลา พร้อมรายการ SHA-256 สำหรับตรวจความครบถ้วน

ข้อมูลที่ดาวน์โหลดผ่าน Apps Script เป็นข้อมูลที่เว็บได้รับจากระบบ ณ เวลานั้น การสำรอง Google Sheet ทั้งไฟล์ รวมสูตรและแท็บอื่น ต้องทำจากต้นฉบับใน Google Drive เพิ่มเติม

ไฟล์ใน `HSEduTrack Backups` บน Google Drive เป็นสำเนาคะแนนรายวันที่ตั้งด้วย `installDailyBackup` ใน Apps Script ส่วน Git เก็บประวัติโค้ด ไม่ใช่สำเนาคะแนน

## การโหลดข้อมูลข้ามเครื่อง

- ปุ่ม **โหลดข้อมูลล่าสุด** อยู่ด้านบน ใช้ได้ทั้งหน้าครูและนักเรียน พร้อมเวลาโหลดสำเร็จ
- เว็บโหลด Google Sheet ตอนเปิดหน้า เมื่อกลับมาที่แท็บ/หน้าต่าง และเมื่ออินเทอร์เน็ตกลับมา
- เมื่อโหลดสำเร็จ หน้าครู สถิติ และผลคะแนนนักเรียนที่เปิดอยู่จะใช้ข้อมูลใหม่
- หากกำลังกรอก เปิดหน้าต่างย่อย หรือบันทึกข้อมูลอยู่ ระบบพักการโหลดไว้ก่อน หากบันทึกไม่สำเร็จต้องลองบันทึกให้สำเร็จก่อนโหลดใหม่
- หากโหลดล้มเหลว จะแสดงข้อมูลที่มีอยู่พร้อมข้อความแจ้ง และกดโหลดใหม่ได้

การโหลดนี้ไม่ใช่การรับข้อมูลแบบทันทีตลอดเวลา หากเปิดหน้าเดิมค้างไว้ ให้กดโหลดข้อมูลล่าสุด ก่อนสลับไปแก้ข้อมูลบนอีกเครื่องควรรอให้เครื่องแรกบันทึกสำเร็จและอีกเครื่องโหลดสำเร็จแล้ว รูปแบบ Apps Script เดิมยังบันทึกข้อมูลทั้งชุด จึงยังไม่ได้รวมการแก้ไขพร้อมกันจากหลายเครื่อง

เมื่อนำ index.html รุ่นนี้ไปเผยแพร่บน GitHub ให้เปิดเว็บใหม่บนแต่ละอุปกรณ์หนึ่งครั้ง ไม่ต้องแก้ Apps Script สำหรับฟังก์ชันโหลดล่าสุดนี้

## การบันทึกคะแนน

- การแก้หลายช่องต่อเนื่องจะรวมรายการที่ยังไม่ส่งเป็นข้อมูลชุดล่าสุด มีคำขอบันทึกที่กำลังส่งได้ครั้งละหนึ่งรายการ และชุดรอส่งอีกไม่เกินหนึ่งชุด
- เมื่อ Apps Script ส่งหลักฐานว่าเขียนและอ่านกลับสำเร็จ เว็บตรวจ SHA-256 ความยาวข้อมูล และ lastUpdated ให้ตรงกับชุดที่ส่ง จึงแสดงสำเร็จได้โดยไม่ดาวน์โหลดฐานข้อมูลซ้ำ หากไม่มีหลักฐานหรือตรวจไม่ตรง จะใช้การอ่านกลับทั้งชุดตามเดิม
- คำตอบ success อย่างเดียวไม่ถือว่าบันทึกสำเร็จ ต้องมีหลักฐานตรงกับชุดที่ส่ง หรืออ่านกลับมาได้ข้อมูลทั้งชุดตรงกัน ถ้ายังยืนยันไม่ได้จะรักษาคะแนนค้างและแสดงปุ่มลองบันทึกอีกครั้ง
- รายการที่ยังยืนยันไม่ได้เก็บในเครื่อง เมื่อเปิดหน้าใหม่ เว็บตรวจ Sheet ก่อน หากข้อมูลตรงกันจะปลดสถานะค้างเอง หากไม่ตรงจะรักษารายการไว้ให้ลองบันทึกอีกครั้ง
- ถ้า Sheet ส่งข้อมูลที่มีเวลาเก่ากว่าหรือเวลาเดียวกันแต่ข้อมูลไม่ตรงกับชุดที่ยืนยันล่าสุด เว็บแจ้งความไม่ตรงกันและรักษาสำเนาในเครื่อง ไม่แสดงว่าซิงค์สำเร็จ Apps Script ยังตรวจเวอร์ชันก่อนเขียนเพื่อป้องกันเครื่องเก่าบันทึกทับข้อมูลใหม่
- คำขอบันทึกรอคำตอบไม่เกิน 15 วินาที และแต่ละครั้งที่อ่านยืนยันรอไม่เกิน 8 วินาที
- หลังบันทึกเสร็จ ข้อความรอบันทึกจะเปลี่ยนทันที แม้ยังพักการโหลดข้อมูลใหม่เพราะกำลังกรอกหรือเปิดหน้าต่างย่อยอยู่

## การตรวจสอบการใช้งาน

tests/usability.cjs ใช้ Playwright กับ Edge ทดสอบข้อมูลจำลอง แยกที่เก็บข้อมูลสองเบราว์เซอร์เพื่อจำลองสองเครื่อง และดักคำขอ Apps Script ทั้งหมด จึงไม่แก้ Google Sheet จริง ครอบคลุมการเพิ่มชิ้นงาน โหลดข้ามเครื่อง อัปเดตหน้านักเรียน ความผิดพลาดของเครือข่าย การลองใหม่ การป้องกันผลโหลดเก่าทับคะแนนที่เพิ่งแก้ การรวมคิวบันทึก คำตอบบันทึกช้าหรือขาดหาย การหมดเวลาของคำขอ คำตอบ success ที่ไม่ได้บันทึกจริง การย้อนกลับของข้อมูล และการเปิดไฟล์ HTML ในเครื่อง/รีโหลดหลังบันทึก

รันด้วย Node ที่ติดตั้ง Playwright แล้ว:

```powershell
node tests/usability.cjs
```

ตั้ง BROWSER_EXECUTABLE หากต้องการใช้เบราว์เซอร์ที่ติดตั้งไว้ตำแหน่งอื่น


## ความเร็วและการใช้งานต่อเนื่อง (30 กันยายน 2026)

- CSS ของ Tailwind สร้างไว้ใน `assets/app.css` หน้าเว็บไม่ต้องดาวน์โหลดตัวแปลง Tailwind จาก CDN ทุกครั้ง ส่วน QR และเสียงจะโหลดเมื่อใช้ฟังก์ชันนั้น ฟอนต์ไม่กั้นการแสดงหน้าเว็บ
- พื้นหลังใช้ `assets/landing-illustration.webp` ขนาดประมาณ 54 KB โดยเก็บ PNG ต้นฉบับไว้ด้วย
- กรอกคะแนนแล้วกด Enter หรือแตะนอกช่องเพื่อยืนยันช่องนั้น คะแนนและผลรวมบนจออัปเดตทันที ระหว่างส่งขึ้น Sheet สามารถกรอกช่องถัดไปได้ คำว่าบันทึกสำเร็จยังต้องรอหลักฐานจากเซิร์ฟเวอร์
- ค่าที่ไม่ใช่ตัวเลขหรือเป็น Infinity จะไม่ถูกแปลงเป็นคะแนนว่าง ไม่ส่งซ้ำเมื่อค่าเดิมไม่เปลี่ยน และไม่สร้างตารางใหม่เมื่ออ่านได้ข้อมูลชุดเดิม
- เน็ตกลับมาแล้วจะตรวจรายการค้างและลองส่งอีกครั้งเมื่อยังมีเซสชันครู โดยไม่ลองทับกรณี CONFLICT หากปิดหน้าขณะมีคะแนนค้าง เบราว์เซอร์จะแจ้งเตือน รายการค้างยังเก็บในเครื่องตามเดิม
- การปรับครั้งนี้ใช้ receipt ที่มีอยู่ใน Code.gs รุ่นปัจจุบัน ไม่ต้องเปลี่ยน Apps Script สำหรับการเร่งการบันทึกนี้

เมื่อแก้คลาส Tailwind ใน HTML หรือ JavaScript ให้สร้าง CSS ใหม่ด้วย `npm ci` (ครั้งแรก) แล้ว `npm run build:css` และตรวจหน้าที่แก้ทุกครั้ง เวลาเผยแพร่ต้องคัดลอก `assets/` ไปด้วย ไม่ใช่เฉพาะ index.html; ยังไม่ต้องนำขึ้น GitHub จนกว่าผู้ใช้จะสั่ง

`tests/sync-performance.cjs` ทดสอบ receipt จริงจาก Code.gs, คิวกรอกต่อเนื่อง, หลักฐานผิด, คะแนนไม่ใช่ตัวเลข, เน็ตหลุด/กลับมา, การไม่สร้างตารางซ้ำ และส่วนเสริม QR/เสียงล้มเหลว ใช้ข้อมูลจำลองทั้งหมด และไม่เขียนคะแนนจริง
