# HSEduTrack

## อ่านคะแนนตรงจาก Google Sheets (รุ่น 2026-10-06)

การตรวจเว็บออนไลน์วันที่ 6 ต.ค. พบการอ่านผ่าน Apps Script ใช้ 9–16 วินาที และมีรอบหมดเวลาประมาณ 28 วินาที ก่อนรับข้อมูลครบ รุ่นนี้อ่านข้อมูลจากชีต `DatabaseChunks` ผ่าน Google Sheets Query ก่อน เพราะชีตเดิมอนุญาตให้อ่านได้อยู่แล้ว ไม่มีการแก้สิทธิ์แชร์ ย้ายฐานข้อมูล หรือเก็บคะแนนลงเครื่อง

ตัวอ่านเลือกคอลัมน์ที่ manifest ยืนยันว่าใช้งานอยู่ ตรวจจำนวนชิ้นข้อมูล ความยาว UTF-8 และ SHA-256 ก่อนนำข้อมูลไปแสดง ใช้คำขอไม่ส่ง cookies พร้อม cache buster ถ้าเส้นทางตรงยังไม่ตอบภายใน 1.2 วินาทีหรืออ่านไม่ผ่าน จะเริ่ม Apps Script เดิมเป็นทางสำรอง ยกเลิกคำขอที่เหลือหลังได้ข้อมูลที่ผ่านตรวจ มี deadline รวมเดิม จึงไม่ปล่อย spinner ค้างไม่สิ้นสุด หากชีตกลับเป็นส่วนตัวหรือเบราว์เซอร์บล็อกทางอ่านตรง ยังใช้ Apps Script ได้

ระบบบันทึก เข้าระบบครู ยืนยันผลบันทึก และตรวจความสามารถเซิร์ฟเวอร์ยังใช้ Apps Script เดิมทั้งหมด ไม่ใช้ Query เพื่อยืนยันการเขียน และไม่รับข้อมูลเก่ามาทับคะแนนที่ยืนยันใหม่กว่า ช่วงโหลดครั้งแรกยังต้องรับข้อมูลออนไลน์หนึ่งครั้ง ผลเวลาในการทดสอบไม่รับประกันว่าเครือข่ายทุกเครื่องจะเร็วเท่ากัน

ทดสอบข้อมูลจริงแบบอ่านอย่างเดียว 6 รอบใน Edge/Chrome ด้วยต้นทาง HTTPS ของเว็บ: อ่านข้อมูลประมาณ 0.49–1.17 วินาที ไม่มี JavaScript error และไม่มีคำขอเขียนคะแนน การเปิด `index.html` ด้วย `file://` อาจถูก Google บล็อกทางอ่านตรง จึงใช้ Apps Script สำรอง ควรใช้เว็บออนไลน์สำหรับเส้นทางอ่านเร็ว

ตรวจเพิ่มเติมด้วย `tests/direct-sheet-read.cjs`, `tests/direct-sheet-read-browser.cjs`, `tests/cloud-read-transport.cjs` และ `tests/save-stability.cjs`: ข้อมูลภาษาไทย/emoji คอลัมน์ active ทั้งสองฝั่ง ข้อมูลไม่ครบ/hash ผิด fallback คำขอค้าง deadline ยกเลิก และคะแนนเก่าที่ตอบช้าไม่ทับคะแนนใหม่ ทุกการเขียนในการทดสอบเป็นข้อมูลจำลอง วิธีเชื่อมต่อใช้ [Google Sheets Query](https://developers.google.com/chart/interactive/docs/spreadsheets) รุ่นนี้ไม่ต้อง Deploy Apps Script เพิ่ม

## แม่แบบ Excel และนำเข้าคะแนน (รุ่น 2026-10-06)

หน้าครู → เลือกห้อง → **ไฟล์คะแนน Excel**

1. **ดาวน์โหลดคะแนนไปแก้ออฟไลน์**: ได้ไฟล์ `.xlsx` พร้อมคะแนนปัจจุบัน รายชื่อ รหัสนักเรียน และชิ้นงานของห้องที่เลือก หรือเลือก **ดาวน์โหลดแม่แบบคะแนนว่าง** เพื่อเริ่มกรอกใหม่
2. เปิดไฟล์ใน Excel และกรอกคะแนนได้โดยไม่ต้องเชื่อมต่อเว็บ ไฟล์เป็นเซลล์ปกติพื้นขาว มีหัวคอลัมน์แถวแรก นักเรียนหนึ่งคนต่อหนึ่งแถว ไม่มีการ์ดหรือกรอบแบบเว็บ กรอกในคอลัมน์ชิ้นงาน จิตพิสัย กลางภาค ปลายภาค หรือคะแนนพิเศษจากครู คะแนนรวมและเกรดคำนวณจากสูตร `SUM`, `MIN`, `ROUND` และ `IF` ใน Excel ตามเกณฑ์เดียวกับเว็บ
3. กลับมาเลือกไฟล์ `.xlsx` หรือ `.csv` ตรวจห้อง จำนวนช่องที่เปลี่ยน งานใหม่ และเปิด **ดูรายการคะแนนที่เปลี่ยน** เพื่อตรวจค่าเดิมกับค่าใหม่
4. เมื่อออนไลน์ กด **ยืนยันนำเข้าและบันทึกคะแนน** หนึ่งครั้ง คะแนนที่แก้ในไฟล์จะอัปเดตในเว็บ ระบบใช้คิวบันทึกและการยืนยันจาก Google Sheet ชุดเดิม สถานะบันทึกสำเร็จขึ้นหลังเซิร์ฟเวอร์ยืนยัน การดาวน์โหลดและอัปโหลดต้องใช้อินเทอร์เน็ต ส่วนการแก้ใน Excel ทำออฟไลน์ได้

### ไฟล์ที่มีจำนวนงานต่างกัน

- จำนวนและลำดับคอลัมน์งานเปลี่ยนได้ จับคู่ด้วยชื่อชิ้นงาน พร้อมรหัสนักเรียนและห้อง ไม่อิงลำดับแถว จำนวนงานของแต่ละห้องจึงไม่ต้องเท่ากัน
- งานเดิมใช้ชื่อให้ตรงในเว็บ ระบุคะแนนเต็มได้ เช่น `UNIT 1 (เต็ม 5)` หรือ `UNIT 1(5)` หากระบุคะแนนเต็มต่างจากเว็บ ระบบจะให้แก้ไฟล์ก่อน
- เพิ่มงานใหม่โดยเพิ่มคอลัมน์ `ชื่อชิ้นงาน (เต็ม 10)` เปลี่ยนชื่อและคะแนนเต็มตามจริง (มากกว่า 0 ถึง 100) ระบบสร้างชิ้นงานจากหัวคอลัมน์ โดยเก็บงานอื่นที่ไม่ได้อยู่ในไฟล์ไว้
- ไฟล์มีหลายชีตและหลายห้องได้ แต่ละห้องมีหัวงานของตนเอง ใส่คอลัมน์ `ห้อง` ให้ตรงชื่อในเว็บ หากไม่มีคอลัมน์นี้ ระบบใช้ห้องที่เลือกและแจ้งในหน้าตรวจ
- ต้องมีคอลัมน์ `รหัสนักเรียน` และเป็นนักเรียนที่อยู่ในห้องนั้นแล้ว รหัสที่มีศูนย์นำหน้าเก็บเป็นข้อความในแม่แบบ ไม่เปลี่ยนชื่อ เลขที่ หรือสร้างนักเรียนจากไฟล์คะแนนนี้
- ไฟล์ภายนอกต้องมีหัวคอลัมน์ที่ระบุความหมายได้ ไม่รองรับตารางที่ไม่มีหัวหรือไฟล์ `.xls` เก่า ให้บันทึกเป็น `.xlsx` ก่อน ขนาดสูงสุด 5 MB, 5,000 แถวและ 250 คอลัมน์ต่อชีต

### ช่องว่าง คะแนนศูนย์ และสถานะ

Excel ที่ดาวน์โหลดแสดงเฉพาะตัวเลขในช่วงคะแนน ช่องยังไม่ส่งและส่งแล้วรอตรวจเป็นช่องว่าง เพื่อคัดลอกช่วงคะแนนไปวางในโปรแกรมอื่น เช่น Bookmark โดยไม่มีข้อความปน คะแนนศูนย์จริงยังแสดง `0` ส่วนคะแนนรวมและเกรดคำนวณได้ตามปกติ ช่องว่างที่อัปโหลดกลับไม่เปลี่ยนคะแนนหรือสถานะเดิม หากต้องการเปลี่ยนสถานะอย่างชัดเจน สามารถพิมพ์ค่าตามตารางด้านล่าง ก่อนวางคะแนนในโปรแกรมอื่นต้องตรวจลำดับนักเรียนและคอลัมน์ให้ตรงกัน

| ค่าในช่อง | ผลเมื่อนำเข้า |
| --- | --- |
| ช่องว่าง | ไม่แก้คะแนนเดิม ใช้สำหรับนำเข้าเฉพาะบางงาน |
| `0` | คะแนนศูนย์จริง ถือว่าตรวจแล้ว |
| ตัวเลข | คะแนนชิ้นงานต้องไม่เกินคะแนนเต็ม จิตพิสัยไม่เกิน 10 สอบแต่ละประเภทไม่เกิน 20 |
| `ยังไม่ส่ง` หรือ `-` | ล้างคะแนนช่องนั้นเป็นยังไม่ส่ง |
| `รอตรวจ` หรือ `ส่งแล้ว` | ชิ้นงานส่งแล้วรอครูตรวจ |

คะแนนรวม คะแนนเก็บรวม และเกรดในไฟล์ไม่นำเข้าทับ เว็บคำนวณเองตามสูตรเดิม ถ้ารหัสไม่ตรง คะแนนผิดช่วง หัวงานซ้ำ หรือคะแนนคนเดียวกันช่องเดียวกันซ้ำในไฟล์ จะไม่บันทึกทั้งไฟล์ หากข้อมูลเว็บเปลี่ยนระหว่างตรวจหรือมีคะแนนรอยืนยัน จะต้องแก้รายการค้าง/เลือกไฟล์ใหม่ก่อน

ปุ่มส่งออก CSV เดิมยังใช้ได้ รุ่นนี้ส่งออกงานที่ยังไม่ส่งเป็นช่องว่างเพื่อไม่ปะปนกับศูนย์ **ไฟล์ CSV เก่าที่ส่งออกสถานะยังไม่ส่งเป็น 0 ไม่สามารถแยกจากคะแนนศูนย์จริงได้** ตรวจไฟล์นั้นก่อนนำกลับเข้า ส่วน CSV รายชื่อสำหรับเพิ่มนักเรียนยังเป็นเครื่องมือแยกต่างหาก

โมดูล `assets/score-files.js` และไลบรารี Excel รวมอยู่ในไฟล์เว็บ โหลดไลบรารีเฉพาะตอนดาวน์โหลด/นำเข้า ไม่ส่งไฟล์ไปบริการอ่าน Excel ภายนอก ไม่เปลี่ยน Apps Script หรือสูตรคะแนน ทดสอบด้วย `tests/score-files.cjs`, `tests/score-files-browser.cjs` และ `tests/save-stability.cjs` ใช้ข้อมูลจำลอง ไม่มีการเขียนคะแนนจริง การปรับนี้รวมอยู่ในไฟล์เว็บรุ่นนี้

## การอ่านครั้งแรกเมื่อคำขอค้าง (รุ่นในคอม 2026-10-05)

รายงาน `HSEduTrack_connection_report (2).json` ยืนยันว่ารุ่น `20261005-3` ได้ HTML HTTP 404 จากคำขอสำรองหลังเริ่มอ่าน 15.8 วินาที และยกเลิกคำขอหลักที่ยังไม่ตอบ รุ่น `20261005-4` แก้ให้คำขอที่ยังมีโอกาสสำเร็จรอต่อได้เมื่ออีกคำขอล้มเหลว รวมถึง 404 และล้างตัวจับเวลาเดิมก่อนตั้งเวลา retry ไม่มีคำขอที่สาม เพิ่ม hostname ของคำตอบในรายงานโดยไม่เก็บ URL/query/body ตรวจเพิ่มกรณีสำรอง 404 แต่หลักสำเร็จ และทั้งสอง 404 อย่างชัดเจน สถานะบันทึกสำเร็จยังขึ้นเฉพาะหลังเซิร์ฟเวอร์ยืนยัน

ตรวจเว็บออนไลน์รุ่น `4aafea5` พบการอ่านครั้งแรกใน Edge ใช้ 28.1 วินาที: คำขอแรกไม่ได้รับ headers จนครบ 25 วินาที แล้วคำขอสำรองได้ข้อมูลใน 2.1 วินาที รอบอื่นใน Edge/Chrome อ่านได้ประมาณ 2.1–2.3 วินาที ไม่มี JavaScript error รายงานจากเครื่องผู้ใช้รุ่น `20261005-2` เก็บหลังเริ่มอ่าน 8.3 วินาที ยังไม่มีผลสิ้นสุด จึงไม่ใช่หลักฐานว่าโหลดค้างตลอดไป

ตัวอ่านรุ่น `20261005-3` เริ่ม GET สำรองหลัง 3.5 วินาทีเฉพาะการอ่านคะแนนครั้งแรก หากคำขอหลักยังไม่เสร็จ รับข้อมูลที่ผ่านตรวจจากคำขอที่สำเร็จก่อนและยกเลิกอีกคำขอ สูงสุดสอง GET ต่อรอบ ไม่เริ่มสำรองเมื่อคำขอหลักตอบเร็ว ไม่แข่งคำขอบันทึก/ยืนยันคะแนน/ตรวจสิทธิ์ ไม่แก้ main app หรือสูตรคะแนน เก็บรายละเอียดเวลาเริ่มแต่ละคำขอและรับ headers รวมถึงแยก HTML แทน JSON ในรายงาน ไม่มีคะแนนหรือชื่อในรายงาน ทั้งสองคำขอยังมีเวลาสิ้นสุดและการหยุดหมุน ไม่รับประกันว่าเครือข่ายทุกครั้งจะเร็ว

ตรวจด้วย `tests/cold-read-failover.cjs`, `tests/cloud-read-transport.cjs`, `tests/cold-start-recovery.cjs` และ `tests/homework-followup.cjs` ใช้ข้อมูลจำลองเพื่อทดสอบคำขอหลักค้าง สำรองล้มเหลวแต่หลักสำเร็จ ทั้งคู่ค้าง ยกเลิก HTML และการบันทึกเดิม ไม่ต้อง Deploy Apps Script เพิ่มสำหรับการแก้นี้ รุ่นนี้ยังอยู่ในคอมก่อนสั่งเผยแพร่ครั้งถัดไป

## ข้อความตามงานสำหรับ LINE

ในหน้าครู เลือกห้องแล้วกด **ตามงาน / คัดลอกข้อความ** เลือกทุกชิ้นงานหรือเฉพาะงาน เพิ่มกำหนดส่งหรือแก้ข้อความก่อนคัดลอกไปวางใน LINE รายชื่อเรียงเลขที่และรวมทั้งห้องโดยไม่อิงตัวกรองค้นหานักเรียน งานที่ส่งแล้วรอตรวจและคะแนนศูนย์ไม่ถือว่าค้างส่ง หน้าต่างใช้ข้อมูลขณะเปิด พร้อมเวลาอ่าน Sheet ล่าสุดและคำเตือนหากคะแนนยังรอยืนยัน การเปิดและคัดลอกไม่ส่งข้อความหรือเขียนข้อมูลคะแนน ระบบตามงานรวมอยู่ในไฟล์เว็บรุ่นนี้

## นโยบายควิซและคะแนนกิจกรรม

ไฟล์เว็บรุ่นนี้ปิดควิซสำหรับนักเรียนและไม่นับคะแนนควิซ/กาชาในคะแนนรวม เกรด ตารางครู สถิติ และ CSV คะแนนงาน จิตพิสัย สอบ และคะแนนพิเศษจากครูคำนวณตามเดิม ตัวละครและประวัติกิจกรรมยังดูย้อนหลังได้

Apps Script ปฏิเสธ `answerQuiz` ด้วย `QUIZ_DISABLED` ก่อนแก้ข้อมูล ต้อง Deploy Code.gs รุ่นนี้เพื่อปิดการรับคำตอบจากเว็บเก่า ดูขั้นตอนใน [คู่มือปิดควิซ](google-apps-script/QUIZ-LOCK-DEPLOY.md) ไฟล์หน้าเว็บรุ่นนี้ปิดควิซและตัดคะแนนกิจกรรมแล้ว ส่วนการปิดควิซที่เซิร์ฟเวอร์ต้อง Deploy Apps Script แยกต่างหาก

ตรวจด้วย `tests/quiz-lock.cjs`, `tests/security-conflict-backup.cjs` และ `tests/security-browser.cjs` โดยใช้ข้อมูลจำลอง

เว็บตรวจสอบคะแนนนักเรียน โดยใช้ Google Sheet เก็บข้อมูล และ Google Apps Script เป็นตัวกลางรับส่งข้อมูล

เว็บรุ่นนี้ใช้ Google Sheet เป็นแหล่งข้อมูลคะแนนเพียงแห่งเดียว โค้ด Supabase เดิมถูกปิดการซิงค์เพื่อไม่ให้ข้อมูลจากอีกฐานกลับมาทับคะแนน แม้เครื่องเคยเก็บการตั้งค่า Supabase ไว้

## การสำรองข้อมูล

ไฟล์เว็บต้นฉบับก่อนเริ่มใช้ Git อยู่ใน `backups/` แยกโฟลเดอร์ตามวันเวลา พร้อมรายการ SHA-256 สำหรับตรวจความครบถ้วน

ข้อมูลที่ดาวน์โหลดผ่าน Apps Script เป็นข้อมูลที่เว็บได้รับจากระบบ ณ เวลานั้น การสำรอง Google Sheet ทั้งไฟล์ รวมสูตรและแท็บอื่น ต้องทำจากต้นฉบับใน Google Drive เพิ่มเติม

ไฟล์ใน `HSEduTrack Backups` บน Google Drive เป็นสำเนาคะแนนรายวันที่ตั้งด้วย `installDailyBackup` ใน Apps Script ส่วน Git เก็บประวัติโค้ด ไม่ใช่สำเนาคะแนน

## การโหลดข้อมูลข้ามเครื่อง

- คะแนนในหน้าเว็บต้องมาจาก Google Sheet ผ่าน Apps Script เท่านั้น หน้าเว็บไม่เริ่มจากสำเนาใน localStorage; ถ้าโหลดออนไลน์ไม่สำเร็จตั้งแต่ต้น จะไม่ให้ค้นหาคะแนนจากข้อมูลเก่า
- เปิดหน้าแล้วกรอกรหัสและกดค้นหาได้ทันที การค้นหาใช้คำขออ่านแรกที่เริ่มเบื้องหลังร่วมกัน เมื่อได้ข้อมูลจะเปิดคะแนนอัตโนมัติ คะแนนที่อ่านสำเร็จแล้วในแท็บเปิดได้ทันทีโดยไม่รออ่านซ้ำ และตรวจรุ่นล่าสุดเบื้องหลังเมื่อข้อมูลเกิน 15 วินาที กลับมาที่แท็บ หรือกดรีเฟรช หน้าที่เปิดค้างตรวจทุกประมาณ 30–35 วินาทีขณะมองเห็นแท็บ
- Apps Script รุ่นใหม่ใช้ `action=sync` และ `knownSha` ตรวจรุ่นในคำขอเดียว ถ้าไม่มีการเปลี่ยนแปลงจะตอบยืนยันขนาดเล็กโดยไม่ส่งคะแนนทั้งชุด หากคำขอแบบนี้ล้มเหลว ตัวอ่านจะลอง GET ปกติอีกหนึ่งครั้ง ส่วน Apps Script รุ่นเก่ายังตอบข้อมูลทั้งชุดได้
- ถ้าโหลดล้มเหลวหลังจากเคยโหลดสำเร็จในแท็บนี้ เว็บแจ้งว่าข้อมูลที่เห็นเป็นข้อมูลออนไลน์ครั้งก่อน ไม่อ้างว่าเป็นข้อมูลล่าสุด
- หลังอ่านออนไลน์สำเร็จ เว็บลบแคชคะแนนรุ่นเก่าที่เคยเก็บในเครื่อง ยกเว้นสำเนาที่ระบุว่ามีคะแนนค้างซึ่งยังไม่ยืนยัน เพื่อไม่ลบข้อมูลที่อาจต้องกู้คืน; หน้าครูจะแสดงปุ่มดาวน์โหลดสำเนารุ่นเก่าสำหรับตรวจเทียบ
- Google Sheet ไม่มีการส่งข้อมูลแบบ push ถึงทุกหน้าจอ การตรวจทุกประมาณ 30–35 วินาทีเป็น near realtime และขึ้นกับเครือข่าย/เวลาตอบของ Apps Script ถ้าต้องการ realtime จริงและเขียนรายคะแนนโดยไม่ส่งทั้งฐาน ควรย้ายไปฐานข้อมูลที่รองรับ subscription และกำหนดสิทธิ์อ่านรายนักเรียน

## การบันทึกคะแนน

- กรอกคะแนนแล้วตารางอัปเดตทันที แต่ข้อความ “บันทึกสำเร็จ” จะขึ้นต่อเมื่อ Apps Script ยืนยันการเขียนด้วย SHA-256 หรือเว็บอ่านกลับแล้วตรงกับข้อมูลที่ส่ง
- เว็บส่งคำขอบันทึกทีละชุด โดยรวมการกรอกหลายช่องที่รอส่งเป็นชุดล่าสุด และใช้ lastUpdated ป้องกันเครื่องเก่าบันทึกทับข้อมูลใหม่
- คะแนนที่ยังไม่ยืนยันอยู่ในหน่วยความจำของแท็บนี้เท่านั้น หากบันทึกไม่สำเร็จให้กดลองบันทึกอีกครั้งหรือดาวน์โหลดสำเนาคะแนนก่อนปิด/รีโหลดหน้า การปิดหน้าอาจทำให้คะแนนที่ยังไม่ยืนยันหาย
- หลังบันทึกสำเร็จ นักเรียนที่เปิดหน้าอยู่จะเห็นข้อมูลใหม่เมื่อระบบตรวจรอบถัดไป (สูงสุดประมาณ 30–35 วินาที บวกเวลาเครือข่าย) หรือกดโหลดล่าสุด
- `google-apps-script/Code.gs` รุ่นในเครื่องเพิ่ม revision endpoint และอ่านคะแนนโดยไม่รอ write lock ต้องอัปเดต deployment เดิมของ Apps Script ก่อนจึงได้ประโยชน์นี้; หน้าเว็บรองรับ backend รุ่นก่อนระหว่างเปลี่ยนผ่าน

## การตรวจสอบการใช้งาน

tests/usability.cjs ใช้ Playwright กับ Edge ทดสอบข้อมูลจำลอง แยกที่เก็บข้อมูลสองเบราว์เซอร์เพื่อจำลองสองเครื่อง และดักคำขอ Apps Script ทั้งหมด จึงไม่แก้ Google Sheet จริง ครอบคลุมการเพิ่มชิ้นงาน โหลดข้ามเครื่อง อัปเดตหน้านักเรียน ความผิดพลาดของเครือข่าย การลองใหม่ การป้องกันผลโหลดเก่าทับคะแนนที่เพิ่งแก้ การรวมคิวบันทึก คำตอบบันทึกช้าหรือขาดหาย การหมดเวลาของคำขอ คำตอบ success ที่ไม่ได้บันทึกจริง การย้อนกลับของข้อมูล และการเปิดไฟล์ HTML ในเครื่อง/รีโหลดหลังบันทึก

รันด้วย Node ที่ติดตั้ง Playwright แล้ว:

```powershell
node tests/usability.cjs
```

ตั้ง BROWSER_EXECUTABLE หากต้องการใช้เบราว์เซอร์ที่ติดตั้งไว้ตำแหน่งอื่น

## หน้าสรุปนักเรียนและเครื่องมือกรอกคะแนน (ทำในเครื่อง)

สูตรคะแนนและโค้ดบันทึก/ซิงค์ Google Sheet ใช้ชุดเดิม เปิด `index.html` ในเครื่องเพื่อทดลองก่อนเผยแพร่การแก้ครั้งถัดไป

- นักเรียนเห็นคะแนนรวม เกรดตามคะแนนปัจจุบัน โบนัสจากครูและกิจกรรม จำนวนงานค้าง/รอตรวจ/ตรวจแล้ว พร้อมปุ่มกรองรายการ งานที่ได้คะแนน 0 ถือว่าตรวจแล้ว
- ครูค้นหาด้วยชื่อ รหัสนักเรียน หรือเลขที่ได้ ตัวเลข 1–3 หลักค้นเลขที่แบบตรงตัว; เลือกชิ้นงานและสถานะเพื่อกรองรายชื่อได้ โดยการกรองไม่บันทึกหรือแก้ข้อมูล
- Enter บันทึกผ่าน onchange เดิม แล้วไปนักเรียนถัดไปในคอลัมน์เดียวกัน; Shift + Enter ไปคนก่อนหน้า โดยข้ามแถวที่ไม่อยู่ในตัวกรอง หากแถวที่กำลังแก้ไม่ตรงตัวกรอง ระบบจะซ่อนหลังย้ายออกจากแถวนั้น
- ตัวกรองคงอยู่เมื่อโหลดข้อมูลห้องเดิม และล้างเมื่อเปลี่ยนห้อง รายชื่อและหัวตารางยังตรึงระหว่างเลื่อน

ตรวจสอบส่วนนี้ด้วย `node tests/score-workspace.cjs` (ข้อมูลจำลอง ไม่ส่งคะแนนจริง) และชุดเดิม `node tests/sync-performance.cjs` / `node tests/usability.cjs`

## หน้าจอโทรศัพท์และแท็บเล็ต (ทำในเครื่อง)

ไฟล์ assets/mobile.css แยกกฎหน้าจอสัมผัสออกจากโค้ดบันทึกและซิงค์คะแนน เปิด index.html ในเครื่องเพื่อทดลองก่อนเผยแพร่การแก้ครั้งถัดไป

- ปรับส่วนหัว เมนูล่าง และขอบจอให้มีพื้นที่เผื่อ safe area ของ iPhone เมนูล่างซ่อนขณะกรอกข้อความหรือคะแนน เพื่อให้ช่องกรอกใช้พื้นที่ได้เต็มขึ้น
- ช่องกรอกใช้ตัวอักษรอย่างน้อย 16px บนหน้าจอโทรศัพท์ และช่องคะแนนมี inputmode decimal; ยังคงอนุญาตให้ซูมหน้าได้
- หน้านักเรียนจัดชื่อ รูปโปรไฟล์ เกรด สรุปงาน และปุ่มกรองให้เหมาะกับจอเล็ก ส่วนกิจกรรมยังอยู่ต่อจากสรุปคะแนน
- หน้าครูขยายช่องคะแนนและปุ่มติ๊กเป็นพื้นที่กด 44px เว้นระยะไม่ให้ชนกัน ตรึงชื่อระหว่างเลื่อน และเปิดเครื่องมือชิ้นงานด้วยปุ่ม ⋯ บนจอสัมผัส
- โทรศัพท์แนวตั้งที่กว้างไม่เกิน 639px มี **มุมมองกรอกคะแนน**: เลือกชิ้นงาน จิตพิสัย กลางภาค หรือปลายภาค เพื่อแสดงเฉพาะรายชื่อ ช่องที่เลือก และคะแนนรวมในจอเดียว เลือก **ทั้งหมด** เพื่อดูตารางเดิม
- การเลือกคอลัมน์อยู่เฉพาะในแท็บที่เปิด ไม่เขียนคะแนนหรือเก็บลงเครื่อง เมื่อเปลี่ยนห้องจะกลับไปแสดงทั้งหมด เมื่อโหลดข้อมูลห้องเดิมจะคงมุมมองไว้
- การบันทึกยังผ่าน onchange และคิวบันทึกเดิม: กรอกแล้วแตะนอกช่องหรือกด Enter; ปุ่มติ๊กใช้คำสั่งเดิม
- ฟอร์มเพิ่มนักเรียนและเพิ่มชิ้นงานเรียงใหม่บนจอเล็ก หน้าต่างเข้าสู่ระบบและให้ดาวเลื่อนภายในได้เมื่อจอเตี้ยหรือเปิดแนวนอน

ทดสอบด้วย **node tests/mobile-layout.cjs** ใช้ Edge ผ่าน Playwright กับข้อมูลจำลองและดักคำขอ Apps Script ทั้งหมด ครอบคลุม 9 ขนาดจอ (320–1366px) การกดบนจอสัมผัส ตารางไม่ล้นในมุมมองคอลัมน์เดียว การตรึงรายชื่อ หน้าต่างและฟอร์ม การเปลี่ยนห้อง/หมุนจอ และบันทึกปลายภาคกับปุ่มติ๊กผ่านระบบเดิม การตรวจนี้จำลองขนาดจอในเบราว์เซอร์ ยังต้องลองบน Safari ใน iPhone จริงหลังอนุมัติเผยแพร่

นักเรียนค้นหาได้ทันทีระหว่างการอ่านคะแนนครั้งแรก และระบบเปิดผลให้อัตโนมัติเมื่อออนไลน์ตอบกลับ `assets/cloud-read.js` เริ่มอ่านตั้งแต่ต้นหน้า ใช้คำขอเดียวร่วมกับการค้นหา และลองอ่านใหม่อีกหนึ่งครั้งเมื่อเครือข่ายสะดุด การอ่านตรวจรุ่นใหม่รวมอยู่ในคำขอเดียวเมื่ออัปเดต Apps Script รุ่น `EDUTRACK_FAST_READ_V1`

ตรวจด้วย `node tests/fast-online-read.cjs` และ `node tests/fast-online-read-browser.cjs` (ใช้ข้อมูลจำลอง) เว็บยังใช้ Apps Script รุ่นเดิมได้ ส่วนการเปิดใช้ตัวอ่านเร็วฝั่ง Google ให้ทำขั้นตอนอัปเดต Apps Script เมื่อสะดวก

## ค้นหาคะแนนโดยไม่บังจอ

การค้นหาและปุ่มรีเฟรชไม่เปิดหน้ารอบังจอ นักเรียนกรอกรหัสได้ตั้งแต่เปิดหน้า และผลค้นหาเปิดให้อัตโนมัติเมื่อข้อมูลออนไลน์มาถึง ปุ่มค้นหาแสดงสถานะสั้น ๆ ระหว่างรอจริง การพักอ่านเพื่อป้องกันทับข้อมูลที่กำลังแก้ไม่ถือเป็นความผิดพลาดของอินเทอร์เน็ต หากอ่านครั้งแรกไม่สำเร็จจึงแสดงข้อความพร้อมปุ่มลองใหม่ หากเคยอ่านสำเร็จแล้ว คะแนนที่ยืนยันยังแสดงอยู่พร้อมสถานะว่ายังตรวจข้อมูลใหม่ไม่ได้ ไม่มีการเก็บคะแนนถาวรในเบราว์เซอร์

ทดสอบด้วย `node tests/student-search-nonblocking.cjs` และ `node tests/fast-online-read-browser.cjs` ครอบคลุมจอ 320/390/1366px การอ่านช้า/ล้มเหลว การค้นหาระหว่างคำขอแรก การพักอ่าน การยกเลิกคำค้น การใช้ GET ปกติเมื่อคำขอแบบใหม่ล้มเหลว และการรักษาคะแนนที่เพิ่งบันทึก ใช้ข้อมูลจำลอง โค้ดคิวบันทึก การยืนยันผลบันทึก และสูตรคะแนนคงเดิม

## รีเฟรชหลังกรอกคะแนนบนคอม

ช่องคะแนนที่มีค่าตรงกับข้อมูลที่บันทึกแล้วจะไม่พักการอ่านเพียงเพราะเคอร์เซอร์ยังอยู่ในช่อง รองรับการกด Enter เพื่อกรอกต่อในแถวถัดไป ส่วนตัวเลขที่พิมพ์แล้วยังไม่ได้บันทึก คิวบันทึกที่ยังทำงาน และหน้าต่างแก้ไขยังได้รับการป้องกันจากผลอ่านออนไลน์ ตัวกรองรายชื่อ/ชิ้นงานและตัวเลือกมุมมองไม่ถือเป็นการแก้คะแนน

คำขออ่านคะแนนปัจจุบันรอสูงสุด 10 วินาทีต่อครั้ง และลองใหม่ได้อีกหนึ่งครั้งหลังพัก 1 วินาที โดยจำกัดเวลารวม 22 วินาที ไม่มีหน้าโหลดบังจอ การยืนยันผลบันทึกยังต้องตรงกับข้อมูลที่ส่งเสมอ ทดสอบด้วย `node tests/desktop-refresh.cjs` ครอบคลุมการกรอกต่อเนื่อง ช่องคะแนนว่าง คะแนน 0 การกรองระหว่างอ่าน การป้องกันตัวเลขที่ยังพิมพ์อยู่ และคำตอบช้าจำลองที่ยังอยู่ภายในเวลาที่กำหนด


## ลดอาการโหลดและบันทึกค้าง (2 ต.ค. 2026)

- คิวบันทึกมีลำดับความสำคัญเหนือการรีเฟรช ยกเลิกคำขออ่านของหน้าเว็บที่กำลังรอเมื่อเริ่มบันทึก และไม่เริ่มคำขออ่านยืนยันเพิ่มระหว่างรอคำตอบ POST คะแนนบนตารางเปลี่ยนทันทีเหมือนเดิม
- รวมการแก้ไขที่ห่างกันไม่เกิน 250 มิลลิวินาทีก่อนส่งชุดแรก จากนั้นส่งทีละชุดและเก็บชุดล่าสุดที่รอส่ง คำตอบ SHA-256 ที่ถูกต้องยืนยันผลได้โดยไม่อ่านข้อมูลทั้งชุดซ้ำ
- รอคำตอบ POST ได้สูงสุด 30 วินาที อ่านยืนยันได้สูงสุด 20 วินาทีต่อคำขอ และจำกัดความพยายามบันทึกทั้งรอบไว้ 50 วินาที หากยังไม่ยืนยันจะหยุดคิว คืนปุ่มลองใหม่และดาวน์โหลดสำเนา ไม่ทิ้งสถานะหมุนค้าง
- หากคำตอบหายและยังไม่รู้ว่ารายการก่อนหน้าบันทึกแล้วหรือไม่ จะตรวจ Sheet ก่อนลองบันทึกใหม่ ปรับรุ่นตั้งต้นได้เฉพาะเมื่อข้อมูลตรงกับรายการที่แท็บนี้เคยส่งทุกส่วน ข้อมูลใหม่จากเครื่องอื่นยังถูกป้องกันด้วย CONFLICT
- คะแนนล่าสุดที่ยังไม่ยืนยันอยู่ใน RAM ของแท็บนี้ ปิดหรือรีโหลดหน้าอาจสูญเสียส่วนที่ยังไม่ยืนยัน ให้ลองบันทึกหรือดาวน์โหลดสำเนาเมื่อแสดงข้อผิดพลาด ไม่มีการเพิ่มแคชคะแนนถาวรในเครื่อง
- หลังอ่านล้มเหลว เว้นการลองอ่านอัตโนมัติ 30, 60 และสูงสุด 120 วินาทีตามจำนวนครั้งที่ล้มเหลว ปุ่มโหลดล่าสุดยังลองได้ทันที การตรวจตามรอบใช้ช่วงประมาณ 30–35 วินาที และพักคำขออัตโนมัติระหว่างกรอก/บันทึก
- สูตรคะแนน ช่องกรอก และขั้นตอนเข้าสู่ระบบครูคงเดิม ไม่ต้องแก้ Apps Script สำหรับการแก้รอบนี้

ตรวจด้วย `node tests/save-stability.cjs` ครอบคลุมคำตอบช้าเทียบเท่า 20 วินาที คำตอบหายหลังบันทึกจริง รายการที่ไม่เคยบันทึก การยกเลิกรีเฟรชทั้งตัวอ่านหลักและตัวอ่านสำรอง ข้อมูลต่างเครื่อง BUSY การหมดเวลารวม คิวล่าสุดและการรวมการกรอก 100 ครั้ง รวมถึงการพักลองอ่านอัตโนมัติและการลองใหม่ด้วยปุ่ม ทดสอบโดยจำลอง Apps Script และไม่ส่งคะแนนจริง

## ตัวอ่านข้อมูลและการหยุดโหลดค้าง (5 ต.ค. 2026)

- ตัวอ่านอยู่ในช่วงต้นของ `index.html` เป็น `HSCloudTransport` ส่วน `assets/cloud-read.js` เริ่มอ่านล่วงหน้าเท่านั้น หากไฟล์นี้โหลดช้าหรือหาย ตัวอ่านสำรองยังใช้กติกาเดียวกันและไม่สร้างคำขอซ้ำ
- คำขอ Google ทุกทางระบุ `credentials: 'omit'`, `mode: 'cors'`, `redirect: 'follow'`, `cache: 'no-store'` และเพิ่ม `_refresh` ใน URL โดยใช้คำขอ POST แบบ `text/plain` เดิมเพื่อไม่เพิ่ม CORS preflight
- การอ่านเบื้องหลังใช้ AbortController จำกัดเวลา 10 วินาทีต่อครั้ง รวมถึง response body และ JSON มีเวลารวมสูงสุด 22 วินาที การอ่านครั้งแรกและตรวจความสามารถ backend ให้คำขอทำงานได้สูงสุด 25 วินาที รวมไม่เกิน 32 วินาที เพื่อไม่ตัดงานที่ Google ตอบช้าแล้วเริ่มใหม่ ลองใหม่ได้ไม่เกินหนึ่งครั้ง การยกเลิกเพื่อบันทึกคะแนนไม่ลองอ่านใหม่
- คิวรีเฟรชทุกทางตรวจช่วงพัก 30/60/120 วินาทีอีกครั้งก่อนเริ่มคำขอ รวมถึงคิวที่รออยู่ระหว่างอ่านและเหตุการณ์ focus/click/focusout ปุ่มรีเฟรชด้วยผู้ใช้ยังลองได้ทันที
- `finally` คืนตัวควบคุมคำขอและสถานะปุ่ม ไอคอนหมุนเฉพาะขณะอ่านจริง ไม่หมุนตอนพักหรืออ่านล้มเหลว สีเขียวขึ้นเมื่อยืนยันข้อมูลแล้วเท่านั้น
- ข้อผิดพลาดแยก timeout, เครือข่าย, HTTP และ JSON/โครงสร้างข้อมูล Console แสดงเพียงชนิดข้อผิดพลาด จำนวนครั้ง เวลา และ HTTP status ไม่แสดงคะแนน รหัสผ่าน หรือ token ตรวจ metadata ของคำขอล่าสุดได้ด้วย `HSCloudTransport.diagnostics()`
- ขั้นตอนเขียนคะแนน คิวบันทึก การยืนยัน SHA-256/อ่านกลับ การป้องกัน CONFLICT และสูตรคะแนนคงเดิม เวลา POST 30 วินาทีและเวลารวมบันทึก 50 วินาทียังใช้ค่าเดิม ไม่ลอง POST ซ้ำจาก timeout โดยอัตโนมัติ

ทดสอบด้วย `tests/cloud-read-transport.cjs` และ `tests/cloud-read-policy-browser.cjs` ครอบคลุมคำขอและ body ค้าง ข้อมูลผิดรูปแบบ การยกเลิกระหว่างอ่าน/ช่วงพัก Google Cookies คิวรีเฟรชหลังล้มเหลว การหยุดหมุน และตัวอ่านสำรอง ใช้ข้อมูลจำลอง ไม่มีการบันทึกคะแนนจริง ไม่ต้องแก้ Apps Script สำหรับการแก้ครั้งนี้

ความต่างระหว่างโหมดปกติและ Private ยังไม่ยืนยันว่าเกิดจาก Google Auth redirect loop เพราะ Fetch เดิมใช้ค่าเริ่มต้น `same-origin` ซึ่งปกติไม่ส่ง cookies ข้าม origin อยู่แล้ว และ ContentService มี redirect ตามการทำงานปกติ การแก้ครั้งนี้บังคับนโยบาย anonymous และแก้ข้อบกพร่องที่ยืนยันได้ในคิวรีเฟรช/การจำกัดเวลา โดยยังต้องตรวจบนเบราว์เซอร์เดิมที่มีอาการหลังเผยแพร่

## ลูกเล่นหน้าแรกและหน้าคะแนน (ทำในเครื่อง)

`assets/experience.css` และ `assets/experience.js` เพิ่มเส้นตกแต่งบางใต้ช่องค้นหา จุดสีเขียววิ่งจนสุดความกว้างแล้วกลับ ไม่มีข้อความหรือเลขขั้นตอน ปุ่มค้นหามีประกายแสงสั้น ๆ ตอนเปิดหน้า ปุ่มและเมนูมีเอฟเฟกต์สี่เหลี่ยมเมื่อกด การ์ดคะแนนใช้เงาและรายละเอียดสีเขียว พร้อมประกาย 8–12 ชิ้นตอนเปิดคะแนน เอฟเฟกต์ไม่บังปุ่มและหายไปภายในประมาณหนึ่งวินาที ตัวเลขคะแนนจริงแสดงทันที

โมดูลใช้ CSS และ Web Animations ที่อยู่ในเครื่อง ไม่มี CDN, คำขอข้อมูล, แคชคะแนน หรือ JavaScript ที่วนทำงานตลอดเวลา เอฟเฟกต์หยุดเมื่อซ่อนแท็บ/ออกจากหน้า และรองรับปุ่ม “เอฟเฟกต์: ลด” เดิม โค้ด inline สำหรับอ่าน/เขียน Google Sheet สูตรคะแนนและเข้าสู่ระบบไม่เปลี่ยน

ตรวจด้วย `node tests/visual-delight.cjs` และ `node tests/mobile-layout.cjs` ครอบคลุมจอมือถือและคอม การลดการเคลื่อนไหว การกำจัดเอฟเฟกต์หลังจบ และคะแนนที่แสดงตรงกับสูตร ชุดทดสอบใช้ข้อมูลจำลองทั้งหมด การปรับนี้รวมอยู่ในไฟล์เว็บรุ่นนี้

## บันทึกเหตุขัดข้องเป็นครั้งคราว (ทำในเครื่อง)

ตัวอ่านเก็บเวลา ชนิดข้อผิดพลาด จำนวนครั้ง และ HTTP status ล่าสุดไม่เกิน 20 เหตุการณ์ใน RAM รวมถึงความผิดพลาดก่อนลองใหม่ที่สำเร็จ ปุ่ม “ดาวน์โหลดข้อมูลปัญหาการเชื่อมต่อ” อยู่ในรายละเอียดใต้ไอคอนรีเฟรช ดาวน์โหลดรายงานได้แม้ระบบกลับมาโหลดสำเร็จแล้ว รายงานไม่มีคะแนน ชื่อนักเรียน รหัสนักเรียน รหัสผ่าน token หรือ URL ของ Google Sheet ไม่มีการส่งรายงานอัตโนมัติและไม่เก็บประวัติถาวรในเบราว์เซอร์

`assets/connection-report.js` สร้างรายงานเฉพาะเมื่อกดปุ่ม ตัวอ่านและคิวรีเฟรชยังใช้เวลา/กติกาเดิม ไม่มีการเปลี่ยนระบบบันทึก คะแนน หรือสิทธิ์เข้าสู่ระบบ ตรวจด้วย `tests/connection-report.cjs`, `tests/cloud-read-transport.cjs` และ `tests/cloud-read-policy-browser.cjs` การปรับนี้รวมอยู่ในไฟล์เว็บรุ่นนี้

## ใช้งานต่อระหว่างตรวจข้อมูลใหม่ (ทำในเครื่อง)

- การตรวจข้อมูลอัตโนมัติหลังมีคะแนนแล้วทำเงียบ ๆ ไอคอนไม่หมุน เมื่ออ่านใหม่ล้มเหลวจะใช้สถานะสีเทาพร้อมข้อความว่าคะแนนเป็นข้อมูลที่ยืนยันครั้งล่าสุด นักเรียนค้นหาจากข้อมูลนี้ได้ทันที การเปิดหน้าใหม่ครั้งแรกยังต้องรับข้อมูลออนไลน์หนึ่งครั้ง
- หยุดตรวจตามรอบ 30–35 วินาทีเมื่อค้างอยู่หน้าค้นหาที่มีข้อมูลแล้ว เริ่มตรวจอีกครั้งเมื่อค้นหาคะแนน ส่วนหน้าคะแนน ครู และสถิติยังตรวจตามรอบ
- การพิมพ์รหัสผ่านครูไม่ทำให้ทิ้งคำตอบคะแนนหรือเริ่มโหลดซ้ำ หน้าต่างแก้ไขข้อมูลและคะแนนที่กำลังกรอกยังมีการป้องกันข้อมูลทับ
- หากคำตอบมาถึงตอนเปิดหน้าต่างอื่น เก็บคำตอบไว้ใน RAM ไม่เกิน 30 วินาทีและใช้ต่อได้เมื่อปิดหน้าต่าง หากมีการแก้ไข/บันทึกระหว่างนั้นหรือคำตอบหมดอายุ จะทิ้งคำตอบนั้นและอ่านใหม่
- คิวเขียนคะแนนและการยืนยันว่าบันทึกสำเร็จยังทำงานตามเดิม ทดสอบด้วยข้อมูลจำลองใน `tests/student-search-nonblocking.cjs`, `tests/cloud-read-policy-browser.cjs`, `tests/desktop-refresh.cjs` และ `tests/save-stability.cjs` ไม่มีการเขียน Google Sheet จริง

## แก้การหมดเวลาครั้งแรกและปรับ Apps Script

พบรายงานจริงที่อ่านสำเร็จหลายรอบก่อนหมดเวลาที่ 10 วินาทีสองครั้ง จึงปรับเวลาสำหรับการอ่านครั้งแรกตามรายละเอียดข้างต้น และหยุดการเริ่มโหลดครั้งแรกใหม่อัตโนมัติไม่สิ้นสุดหลังหมดเวลา ปุ่มค้นหา/รีเฟรชยังลองใหม่ได้ รายงานเชื่อมต่อเพิ่มช่วง `headers`, `body`, `validate` และแยกรหัสข้อผิดพลาดที่ Apps Script ส่งกลับ

`google-apps-script/Code.gs` รุ่น `2026-10-05-stable-read-2` ลดการอ่าน manifest ซ้ำ รองรับแคชขนาดใหญ่โดยแบ่งส่วนและตรวจ SHA ทุกรอบ และรับมือการสลับคอลัมน์จากการบันทึกระหว่างอ่านหนึ่งครั้ง การอ่านยืนยันบันทึกยังอ่าน Sheet โดยตรง ขั้นตอนอัปเดตอยู่ใน [คู่มือ Deploy สคริปต์](google-apps-script/READ-STABILITY-DEPLOY.md) ต้องอัปเดต Web app เดิมก่อนส่วนแก้ฝั่ง Google จะทำงาน

ตรวจด้วย `tests/cold-start-recovery.cjs` (จำลองคำตอบ 18 วินาที, คำขอค้าง, ไม่มีไฟล์ช่วยโหลด และการลองใหม่), `tests/cloud-read-transport.cjs`, `tests/fast-online-read.cjs`, `tests/apps-script-storage.cjs`, `tests/fast-online-read-browser.cjs`, `tests/student-search-nonblocking.cjs`, `tests/cloud-read-policy-browser.cjs` และ `tests/save-stability.cjs` ทุกการบันทึกในการทดสอบเป็นข้อมูลจำลอง
